section-1. QuerySet API — filter, exclude, annotate, aggregate, Q objects, F expressions

Q1. What is a QuerySet? Why is it called 'lazy'? When does Django actually hit the database?
-> QuerySet is a collection of database objects. It is LAZY because The query runs only when Django needs the results, keep modifying the QuerySet no database query is sent.

Q2. Write a query to get all active products with price between 100 and 1000, ordered by price
ascending.(model in shop_project: app->products)
>>> from products.models import Product
>>> product = Product.objects.filter(is_active=True, price__range=(100,1000)).order_by('price')
>>> product
<QuerySet [<Product: Mouse>]>

Q3. What are Q objects? Write a query to find products that are EITHER priced under 500 OR have
stock over 200.
->Q objects allow you to build OR, NOT, and nested combinations using | (OR), & (AND), and ~ (NOT) operators.
>>> from products.models import Product
>>> from django.db.models import Q
>>> product = Product.objects.filter(Q(price__lt=500)|Q(stock__gt=200))
>>> product
<QuerySet [<Product: Keyboard>, <Product: Pen>, <Product: headphones>]>

Q4. Use F() to atomically decrement the stock of Product with pk=7 by 3 units. Why is F() safer than
fetching and saving?
->F() safer than fetching and saving, because it solve the race condition ocuured in fetching and saving.
Product.objects.filter(pk=7).update(
    stock=F('stock') - 3
)

Q5. What is the difference between aggregate() and annotate()? Write one example of each.
ans:
aggregate():
-> Calculates a summary value for the entire QuerySet, Return Type: Dictionary

from django.db.models import Avg

result = Product.objects.aggregate(
    avg_price=Avg('price')
)

annotate():
-> Adds a calculated value to each object in the QuerySet Return type: QuerySet

from django.db.models import Count

categories = Category.objects.annotate(
    product_count=Count('product')

section-2: Model Relationships — ForeignKey, ManyToManyField, OneToOneField

Q1. Difference Between ForeignKey and OneToOneField
ForeignKey:
Relationships -> One-to-many
example:many products in one category
class Product(models.Model):
    category = models.ForeignKey(
        Category,
        on_delete=models.CASCADE
    )

OneToOneField:
Relationships -> One-to-one
example: one profile to one user
class Profile(models.Model):
    user = models.OneToOneField(
        User,
        on_delete=models.CASCADE
    )

Q2. Define a 'Student' model and a 'Course' model with a ManyToMany relationship. How would you enroll a student in a course using ORM?
Models:
class Course(models.Model):
    name = models.CharField(max_length=100)


class Student(models.Model):
    name = models.CharField(max_length=100)
    courses = models.ManyToManyField(Course)

Enroll Student:
student = Student.objects.get(id=1)
course = Course.objects.get(id=1)

student.courses.add(course)

Q3. What is a 'through' model? When would you use it instead of a plain ManyToManyField?
A through model is a custom intermediary table for ManyToMany relationships.
Use it when you need extra fields in the relationship.

Q4. What does related_name do? What happens if you don't set it? Write an example using related_name to fetch all products of a category.
related_name defines the reverse lookup name.
Fetch all products of a category:
category = Category.objects.get(id=1)

category.products.all()

If related_name is not set Django creates: category.product_set.all() , Default reverse name: <model_name>_set

Q6. What is the difference between CASCADE and PROTECT for on_delete? Give a situation where PROTECT is the better choice.
CASCADE:
When parent is deleted, child records are also deleted.
PROTECT:
Prevents deletion if related records exist.
PROTECT is better:
Banking System, You should not delete an Account if Transactions exist because financial history must be preserved.
